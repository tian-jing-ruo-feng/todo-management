# 编码规范

本文档定义了 Todo Management 项目的编码规范，确保代码风格一致性和可维护性。

## 命名约定

### 文件命名

- **组件文件**：使用 PascalCase，例如 `TaskCreateModal.tsx`、`KanbanBoard.tsx`
- **工具文件**：使用 camelCase，例如 `db.ts`、`crypto.ts`
- **类型文件**：使用 PascalCase，例如 `Task.ts`、`Status.ts`
- **Hook 文件**：使用 camelCase，以 `use` 开头，例如 `useCrossColumnDragging.ts`

### 变量和函数命名

- **变量**：使用 camelCase，例如 `taskCount`、`statusList`
- **函数**：使用 camelCase，动词开头，例如 `saveTask`、`deleteTask`、`getAllTasks`
- **常量**：使用 UPPER_SNAKE_CASE，例如 `ENCRYPTION_KEY`、`DATABASE_URL`

### 类和接口命名

- **类**：使用 PascalCase，例如 `ToDoDb`、`Task`
- **接口**：使用 PascalCase，例如 `Task`、`Status`、`Priority`
- **类型别名**：使用 PascalCase，例如 `Task`、`Column`

### 特殊命名

- **布尔变量**：使用 `is`、`has`、`should` 等前缀，例如 `isRemoved`、`isTop`、`isSharable`
- **事件处理函数**：使用 `handle` 前缀，例如 `handleOk`、`handleCancel`、`handleTaskUpdate`
- **异步函数**：使用 `async` 关键字，返回 Promise，例如 `saveTask: async (task: Task) => Promise<string>`

## 代码风格

### 导入顺序

导入语句应按照以下顺序组织：

1. 第三方库导入
2. 内部模块导入（使用 `@/` 别名）
3. 相对路径导入
4. 类型导入（单独分组）

```typescript
// 第三方库
import { Form, Modal } from 'antd'
import { useState } from 'react'
import Dexie from 'dexie'

// 内部模块（使用 @ 别名）
import type { Task } from '@/types/Task'
import { saveTask } from '@/utils/db'

// 相对路径
import KanbanColumn from './KanbanColumn'

// 类型导入
import type { DragEndEvent } from '@dnd-kit/core'
```

### 注释规范

#### 文件注释

每个文件应包含简短的说明注释，描述文件的用途。

```typescript
/**
 * 任务数据库操作工具
 * 提供任务的增删改查功能
 */
```

#### 函数注释

使用 JSDoc 格式的注释，包含参数说明、返回值说明和功能描述。

```typescript
/**
 * 添加或更新任务
 * @param task 任务对象，如果包含id则为更新，否则为添加
 * @returns Promise<string> 返回任务ID
 */
export const saveTask = async (task: Task): Promise<string> => {
  // ...
}
```

#### 接口和类型注释

为接口属性添加注释说明。

```typescript
export interface Task {
  /**
   * 任务ID
   */
  id: string

  /**
   * 任务名称
   */
  name: string

  /**
   * 任务状态
   */
  status: string
}
```

#### 代码注释

对于复杂逻辑，使用单行注释说明。

```typescript
// 按sort倒序排列（sort值大的在上面）
grouped[columnId].sort((a, b) => {
  const sortA = a.sort ?? 0
  const sortB = b.sort ?? 0
  return sortB - sortA
})
```

### TypeScript 类型定义

#### 接口定义

优先使用 `interface` 定义对象类型。

```typescript
interface Task {
  id: string
  name: string
  content?: string
}
```

#### 类型别名

使用 `type` 定义联合类型或复杂类型。

```typescript
type Column = {
  id: string
  title: string
  color?: string

```

#### 泛型使用

对于可复用的组件或函数，使用泛型。

```typescript
interface Table<T> {
  add(item: T): Promise<string>
  update(id: string, changes: Partial<T>): Promise<number>
}
```

### 函数定义

#### 函数声明

使用箭头函数定义组件和函数组件。


对于对象参数，使用解构赋值。


为可选参数提供默认值。

```typescript
  // ...

```

### 异步处理

#### 使用 async/await

优先使用 `async/await` 而非 Promise 链。

```typescript
export const saveTask = async (task: Task): Promise<string> => {
  if (task.id && (await db.tasks.get(task.id))) {
    await db.tasks.update(task.id, updateData)
    return task.id
  }
  // ...
}
```

#### 错误处理

使用 try-catch 处理异步错误。

```typescript
const handleOk = async () => {
  try {
    setLoading(true)
    const values = await form.validateFields()
    onSave(newTask)
  } catch (error) {
    console.error('创建任务失败:', error)
  } finally {
    setLoading(false)
  }
}
```

## 最佳实践

### React Hooks 使用

#### 基本 Hooks

- **useState**：用于组件状态管理
- **useEffect**：用于副作用处理
- **useCallback**：用于函数记忆化，避免不必要的重渲染
- **useMemo**：用于值记忆化，避免重复计算
- **useRef**：用于保存可变值或 DOM 引用

```typescript
const [tasks, setTasks] = useState<Task[]>([])
const [loading, setLoading] = useState(false)
const draggedTaskRef = useRef<Task | null>(null)

const handleTaskUpdate = useCallback(async (updatedTask: Task) => {
  await saveTask(updatedTask)
  setTasks((prev) => ...)
}, [])

const sortedTasks = useMemo(() => {
  return tasks.sort((a, b) => (b.sort ?? 0) - (a.sort ?? 0))
}, [tasks])
```

#### 自定义 Hooks

将可复用的逻辑封装为自定义 Hook，命名以 `use` 开头。

```typescript
export function useCrossColumnDragging({
  tasksByColumn,
  setTasksByColumn,
}: UseCrossColumnDraggingProps) {
  const handleCrossColumnMove = useCallback(async (event) => {
    // ...
  }, [])

  return { handleCrossColumnMove }
}
```

### 性能优化

#### 使用 useCallback 缓存函数

对于传递给子组件的回调函数，使用 `useCallback` 缓存。

```typescript
const handleEditTask = useCallback((task: Task) => {
  setEditingTask(task)
  setModalVisible(true)
}, [])
```

#### 使用 useMemo 缓存计算结果

对于昂贵的计算，使用 `useMemo` 缓存结果。

```typescript
const groupedTasks = useMemo(() => {
  const grouped: Record<string, Task[]> = {}
  columns.forEach((col) => {
    grouped[col.id] = tasks.filter((t) => t.status === col.id)
  })
  return grouped
}, [tasks, columns])
```

#### 避免不必要的渲染

使用 React.memo 或 useMemo 避免不必要的组件重渲染。

### 条件渲染

使用条件运算符进行简洁的条件渲染。

```typescript
{activeTask ? (
  <div className="rotate-3 shadow-2xl scale-105">
    <KanbanItem task={activeTask} isDragging={true} />
  </div>
) : null}
```

### 列表渲染

使用 `map` 进行列表渲染，提供唯一的 `key`。

```typescript
{columns.map((column) => (
  <KanbanColumn
    key={column.id}
    id={column.id}
    title={column.title}
    tasks={tasksByColumn[column.id] || []}
  />
))}
```

### 错误处理

#### 控制台日志

使用 `console.error` 记录错误信息。

```typescript
try {
  await saveTask(task)
} catch (error) {
  console.error('保存任务失败:', error)
}
```

#### 用户提示

使用 Modal 或 message 提示用户错误信息。

```typescript
Modal.confirm({
  title: '确认删除任务？',
  content: '删除后将无法恢复，请确认是否删除。',
  onOk: async () => {
    try {
      await deleteTask(task.id)
    } catch (error) {
      console.error('删除任务失败:', error)
    }
  },
})
```

## 路径别名

使用 `@/*` 别名导入 `src` 目录下的文件。


## 总结

遵循以上编码规范，可以确保代码：

- **一致性**：团队代码风格统一
- **可读性**：代码易于理解和维护
- **可维护性**：便于后续扩展和修改
- **类型安全**：充分利用 TypeScript 类型系统
- **性能优化**：避免不必要的重渲染和计算
